# BAS-001：BTC/ETH 分年度历史平均 Funding 模型

## 研究口径
BAS-001 采取**两套收益口径**，仅用于离线经济收益估算，不篡改 ALGOGENE V8.1 原始策略：
1. `net_pnl_ex_funding_usd`：基差交易毛收益减去按成交名义额计算的手续费、额外滑点和实际融资成本。
2. `net_pnl_including_estimated_funding_usd`：上项加上按 BTC/ETH **各自年份**历史平均 Funding 费率折算的估算现金流。

Funding 正值代表永续空头预计收到资金费用，负值表示预计支付。**逐年平均是近似估算，不是实际每次结算到账金额。**

## 数学公式
在第 y 年覆盖的持有时段：
```
Estimated_Funding(y)
  = Perp_Open_Notional_USD × Annual_Mean_Funding_Rate(y) × Holding_Hours_In_Year(y) / 8760
```
总 Funding 取每个自然年度的估计值之和。比如 12 月 31 日开仓、1 月 1 日平仓，会按跨年边界分段，不使用固定五年均值。当前统一使用每年 365 天（8760 小时）的年化约定；报告必须说明这个约定，闰年也采用相同年化基数。

`annual_rate_pct` 使用**百分数**，例如 6 代表年化 6%，而不是 0.06；可以为负值。手续费/额外滑点则使用小数费率，如 `0.0005=0.05%`。

## 费率数据结构
`config/annual_funding_rates_template.csv` 为**只有表头的空白模板**：
```csv
symbol,year,annual_rate_pct,source
```
使用前应依据核实后的历史来源，为 BTC 和 ETH 的每个相关年份分别填写费率和出处。缺失任何币种或年份、空出处、重复键都会报错，**不得用 0、复制 BTC 费率给 ETH 或虚构数值填空**。

`tests/fixtures/annual_funding_synthetic.csv` 的费率为**人工合成测试数据**，不可用作历史回测研究结论。历史原始逐次数据可用于计算各年均值，但需要先核实所选平台与合约结构；Binance BTCUSDT 和 ALGOGENE BTCUSDM 不可默认等同。

## 数据计算原则
如果根据历史逐次结算记录构造年均费率：同一年度实际结算费率的累计和，除以完整覆盖的年数（完整自然年以对应实际天数计）再换算为统一 365 天年化。结算记录不完整或合约已变更计费规则时必须报告缺失。理想情况下，应以逐次结算对应的仓位名义额加权，但此处选用年度平均模型，存在近似误差。

## 成本口径
- 买卖价差：由现货 Ask/Bid、永续 Bid/Ask 成交价体现，不额外重复扣除。
- 手续费：四次单腿分别按成交名义额 × 实际或明确的假设费率。
- 滑点：四条腿按成交名义额 × 滑点率；实际成交价已含滑点时额外滑点设 0。
- Funding：按 BTC/ETH 各年历史均值估算、与无 Funding 收益并列报告。
- 融资：只对真实借款本金按年化利率和实际持仓时间扣除；没有借款时为零。
- 若平台 NAV 已含交易费用或 Funding，**不可再次从 NAV 扣除/加回**。

```bash
python -m unittest discover -s tests -v

```
测试配置使用人工年均费率与模拟成交，不能称为已完成的 ALGOGENE 回测。真实数据未核实前，仅把**不含 Funding 的交易净收益**作为可解释基准；含 Funding 结果明确标为估算。
